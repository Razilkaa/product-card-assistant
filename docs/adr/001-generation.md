# Решения по архитектуре

Статус: принято, 03.11.2026.

FastAPI и до двух вызовов LLM на товар: генерация и проверка фактов. База данных и очередь не нужны для одиночных запросов из ТЗ.

Характеристики копируются из входа. Модель пишет текст; Pydantic проверяет формат и длину, отдельная проверка отклоняет новые числа. Второй вызов сверяет все поля черновика с исходными данными. Неподтверждённые факты, некорректный вердикт или ошибка проверки блокируют выдачу карточки. Промпты запрещают выполнение инструкций из данных товара.

Совпадающие после удаления пробелов и приведения регистра ключи specs отклоняются. Производитель передаётся только в manufacturer; ключ «Производитель» в specs запрещён. Ошибки входа возвращают 422, ошибки генерации - 502. Повторов нет, чтобы не увеличивать расходы без ведома пользователя.

Ограничения: проверка чисел и повторная проверка той же LLM не гарантируют достоверность текста; перед публикацией нужна проверка менеджером. Второй вызов увеличивает стоимость и задержку. Обязательные характеристики зависят от категории прибора. Следующий шаг - схемы полей по категориям и проверка фактов на размеченных примерах.

Зависимости фиксируются в uv.lock. Разработка, CI и Docker используют uv. Контейнер запускается без root; секреты передаются через окружение.
