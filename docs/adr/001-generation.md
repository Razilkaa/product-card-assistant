# ADR 001: небольшой синхронный по смыслу API без хранения

Статус: принято. Дата: 03.11.2026.

## Контекст

Нужно получить черновики двух товарных карточек, не выдумывая параметры. ТЗ не требует CMS, БД или очереди. Исходный YML может содержать только название и производителя.

## Решение

FastAPI принимает один товар; асинхронный HTTP-клиент вызывает один Chat Completions-совместимый endpoint. Pydantic проверяет вход и выход. Характеристики и список пустых полей собираются кодом. Промпт ограничивает модель фактами входа; дополнительная проверка отклоняет новые числовые значения. Результат всегда требует редакторской проверки.

API возвращает 422 для неверного входа и 502 при отказе upstream либо нарушении контракта. Ответы провайдера и секреты не передаются клиенту. Автоматических повторов нет: для MVP важнее предсказуемый расход и явная ошибка.

## Альтернативы

Шаблоны без LLM проще проверять, но они не выполняют требование вызова LLM API. Агент, RAG и векторная БД не нужны: источник уже передан в запросе. Очередь и хранилище оправданы при пакетной генерации, но не при одиночном черновике.

## Последствия

Мало компонентов, тесты работают без сети, Docker не содержит ключей. Нет истории генераций, фоновых заданий и гарантии фактической точности свободного текста. Реальные результаты нельзя подтвердить без настроенного провайдера; приложенные демонстрации не выдаются за интеграционный тест.
